# UX и product review

## Актуальные приоритеты после PROD reconciliation 0.5.0

- Первое P1-замечание (подмена SQL/обязательного прогресса клиентом) исправлено и подтверждено catalog/security checks в PROD. Оно больше не является рекомендацией открытого backlog.
- Остальные пункты ниже — улучшения, а не релизные блокеры. Для live cross-user/mutation сценариев нужна отдельная изолированная среда; production тестовые попытки не расходовать.
- Настройка leaked-password protection остаётся безопасной Auth-рекомендацией владельцу проекта.

| Приоритет | Проблема | Решение | Ожидаемый эффект |
|---|---|---|---|
| P1 | Клиент сам сообщает системе, что SQL и обязательный блок пройдены | Серверная проверка результата; ясная обратная связь по сохранению попытки | Нельзя пропускать учебные шаги подменой HTTP-запроса; прогресс становится доверенным |
| P1 | Не хватает безопасного тестового контура | Staging Supabase с отдельными student/admin fixtures, фикстурами ДЗ и финального экзамена | Полный E2E по реальному серверу без риска испортить учебный прогресс и попытки |
| P2 | Арчи может расходовать больше токенов при параллельных запросах | Атомарный quota reservation и метрика отказов по лимиту | Предсказуемая стоимость и честное соблюдение настройки запросов/минуту |
| P2 | Большие визуальные ресурсы увеличивают потенциальную загрузку | Перекодировать 1.16 MB pending-иллюстрацию в AVIF/WebP, задать route/component-level lazy-load и бюджет bundle | Быстрее первый экран урока, меньше трафика на mobile |
| P2 | Нельзя понять, какая страница или запрос тормозит для ученика | Неблокирующие RUM-метрики LCP/INP/CLS, server timing для ключевых loader'ов и алерт на p95/error rate | Оптимизация по фактам и раннее обнаружение деградации |
| P2 | Путь домашних заданий проверяется по частям, нет полного сценария ученика/наставника | В staging прогон: черновик → отправка → ожидание → возврат → повторная отправка → принятие, с уведомлениями | Меньше ошибок статусов и более понятное ожидание обратной связи |
| P3 | Администратор не видит, почему импорт не применился или что именно изменится | В preview показывать список блоков, предупреждения по несовместимым полям и diff перед сохранением | Уверенное редактирование контента, меньше случайных замен урока |
| P3 | Ученику трудно отличить обязательный шаг от необязательного материала | Явно показывать «обязательный шаг», сохранение ответа и причину блокировки перехода | Меньше ощущения, что урок завис или шаг не сработал |
| P3 | Аналитика не объясняет размер выборки и свежесть данных единообразно | В карточках показывать период обновления, знаменатель и предупреждение при малой выборке | Меньше неверных выводов у наставника без добавления новых дашбордов |

Пять наибольших эффектов: серверная валидация assessment/progress; изолированный staging E2E; атомарный rate limit Арчи; оптимизация тяжелых assets; p95/CWV мониторинг с порогами. Сначала закрыть P1, затем ранжировать оставшееся по измеренным метрикам.
