# QA Start

Перед работой над любым уроком QA Start обязательно:

1. Прочитать [docs/LESSON_GUIDELINES.md](docs/LESSON_GUIDELINES.md).
2. Посмотреть актуальный День 1 как эталон качества.

## Публикация

- Для отправки изменений в GitHub использовать обычный `git push` напрямую. Не использовать `gh`.
- Постоянное указание владельца проекта: каждое завершённое исправление или добавление сразу выпускать в PROD и отправлять в GitHub после проверок, в рамках текущей рабочей ветки; обновлять patch-версию и `CHANGELOG.md`. Если проверки не прошли, сначала исправить их или остановиться при блокере; PROD не оставлять с непроверенной сборкой. Не пушить в устаревший `main`.

## Контекст проекта

- Перед передачей проекта новому агенту или при необходимости быстро восстановить операционный контекст прочитать [docs/AGENT_HANDOFF_RU.md](docs/AGENT_HANDOFF_RU.md).
